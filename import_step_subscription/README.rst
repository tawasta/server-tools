==========================
Import Step: Subscriptions
==========================

Adds a **Subscriptions + Lines** import step for the ``import_core``
framework.

This module registers:

* Import step: ``subscription``
* Runner model: ``generic.import.runner.subscription``

The step integrates with the generic dispatcher provided by
``import_core``.

Features
========

The subscription import step supports:

* Creating subscriptions
* Reusing existing subscriptions via search fields
* Creating subscription lines
* Reusing existing subscription lines via search fields
* Shared import state integration
* Sequential import chaining
* Automatic subscription-line linking

The module depends on:

* ``import_core``
* ``subscription_oca``

Import step registration
========================

The module registers the following import step:

.. code-block:: xml

    <record id="generic_import_step_subscription" model="generic.import.step">
        <field name="name">Subscriptions + Lines</field>
        <field name="code">subscription</field>
        <field name="sequence">50</field>
        <field name="required_models">
            sale.subscription,sale.subscription.line
        </field>
    </record>

This means:

* The dispatcher executes runner:

  ``generic.import.runner.subscription``

* The step is only available when models:

  * ``sale.subscription``
  * ``sale.subscription.line``

  are installed.

Configuration
=============

1. Install modules:

   * ``import_core``
   * ``subscription_oca``
   * ``import_step_subscriptions``

2. Open:

   ``Imports -> Templates``

3. Create or edit a template

4. Add import step:

   * ``Subscriptions + Lines``

5. Configure field mappings for models:

   * ``sale.subscription``
   * ``sale.subscription.line``

6. Optionally mark fields as:

   * ``Is search field``

Search fields are used to find existing records before creating new ones.

Usage
=====

Subscription import
-------------------

Map CSV/XLSX columns to ``sale.subscription`` fields.

Example mappings:

* ``Reference -> sale.subscription.code``
* ``Start Date -> sale.subscription.date_start``
* ``Next Invoice Date -> sale.subscription.recurring_next_date``

Import behavior:

* Existing subscriptions are reused when search fields match
* New subscriptions are created when no match exists

Example CSV
-----------

.. code-block:: text

    Subscription,Product,Quantity
    SUB-001,Service Product,1

Subscription line import
------------------------

Map CSV/XLSX columns to ``sale.subscription.line`` fields.

Example mappings:

* ``Quantity -> sale.subscription.line.product_uom_qty``
* ``Unit Price -> sale.subscription.line.price_unit``
* ``Discount -> sale.subscription.line.discount``

Import behavior:

* Existing subscription lines are reused when search fields match
* New subscription lines are created when no match exists

Automatic linking
=================

The runner automatically stores created records into shared state.

Subscription:

.. code-block:: python

    state = self._set_state_record(
        state,
        "subscription",
        subscription,
    )

Subscription line:

.. code-block:: python

    state = self._set_state_record(
        state,
        "subscription_line",
        subscription_line,
    )

This allows state links to assign relations automatically.

Typical state link examples
===========================

Subscription to subscription line
---------------------------------

.. code-block:: text

    source_state_key = subscription
    target_model     = sale.subscription.line
    target_field     = sale_subscription_id

Partner to subscription
-----------------------

.. code-block:: text

    source_state_key = partner
    target_model     = sale.subscription
    target_field     = partner_id

Product to subscription line
----------------------------

.. code-block:: text

    source_state_key = product
    target_model     = sale.subscription.line
    target_field     = product_id

Shared import state
===================

The step stores:

* ``state["subscription"]``
* ``state["subscription_line"]``

Automatic model-based state keys are also generated by
``generic.import.runner.base``.

Example:

.. code-block:: python

    state["sale_subscription"]
    state["sale_subscription_line"]

Technical implementation
========================

The runner inherits:

.. code-block:: python

    _inherit = "generic.import.runner.base"

Available helper methods include:

* ``_get_or_create()``
* ``_get_or_create_from_lines()``
* ``_build_domain()``
* ``_clean_vals()``
* ``_set_state_record()``

Import flow
------------

Simplified processing order:

1. Read mapped subscription values
2. Search/create ``sale.subscription``
3. Store subscription into shared state
4. Read mapped subscription line values
5. Search/create ``sale.subscription.line``
6. Store line into shared state
7. Apply configured state links

Search field behavior
=====================

Fields marked as ``Is search field`` are used to build lookup domains.

Example:

* ``code`` marked as search field

The runner performs:

.. code-block:: python

    self.env["sale.subscription"].search([
        ("code", "=", value)
    ], limit=1)

If a matching record is found:

* Existing record is reused
* Duplicate creation is avoided

Dependencies
============

Python dependencies:

* None

Odoo dependencies:

* ``import_core``
* ``subscription_oca``

Known issues / Roadmap
======================

* No automatic updating of existing subscriptions or lines
* No duplicate merging logic
* No advanced validation or normalization
* Partner/product linking depends on configured state links
* Required fields must exist through mappings or state links
